# v2.3.3 PRD: Plugin Type-Check Restoration & Safety-Contract Gap Closure

This document is the product / implementation spec for the **v2.3.3** release of `figma-edit-mcp`. It follows v2.3.2 (Safety Contract Conformance & Atomicity Hardening) and has two tracks:

1. **Type-check restoration (developer infrastructure).** Restore TypeScript type-checking for the Figma plugin source, which is currently silently disabled by a misconfigured `figma_plugin/tsconfig.json`, and add a CI gate so it cannot regress.
2. **Safety-contract gap closure.** Close the three code-level gaps confirmed by the adversarial review of [`figma-edit-mcp-gap-details.md`](figma-edit-mcp-gap-details.md) — design-system updates that skip current-name verification (Gap 1), create-tool schemas that contradict the runtime parent-name requirement (Gap 3), and a batch delete that reports success on partial failure (Gap 5) — plus the additional findings of the 2026-07-10 follow-up review ([`revised-prd.md`](revised-prd.md), live channel `pn68`) that were independently re-verified against the source for this revision: an unusable `annotation_set` contract (Gap 6), batch-contract corrections (Gap 7), implicit-parent containment violations (Gap 8), an unbound plugin/server channel (Gap 10), and string-flattened errors with all-or-nothing page loads (Gap 11). Gaps 2 and 4 remain documentation-only (handled by the README rewording already in the working tree). Gap 9 (connectors) and the follow-up review's heavier prescriptions are **deferred pending explicit decisions** — see the non-goals.


## Release identity

> [!IMPORTANT]
> **This is v2.3.3.** It grants **no new editing powers** and adds no new tools. Track 1 is build/tooling + type-hygiene only, with no runtime behavior change. Track 2 **tightens and repairs** the existing safety contract: previously optional verification fields become required (`currentVariableName`; new `currentStyleName` and `collectionName`; `parentNodeName` at the schema level, now including `create_component_set`); batch success semantics are corrected; the advertised-but-unusable `annotation_set` contract is restored to working order (a behavior fix, not a new permission — called out because callers will observe new successful behavior); input strictness becomes recursive; creations are contained to their verified parents; the channel binds one plugin peer to one MCP session; and plugin errors travel as structured codes. Agents that omitted required fields will now receive structured `Operation Denied` errors instead of unverified writes — an intended fail-closed change, following the v2.2.0 precedent of universalizing name verification. It depends on v2.3.2 being merged first (v2.3.2 is in progress at authoring time).
>
> Version surfaces to bump follow the v2.3.2 mechanism (`package.json`, root `package-lock.json`, both `server.json` fields, root `manifest.json`, and the plugin About handshake — enforced by `check:versions` and `check:plugin`): `2.3.2 → 2.3.3`.
>
> **Versioning policy (open-questions Q5, resolved 2026-07-09: Option A).** The release stays numbered **2.3.3**, and the rule is recorded as policy rather than precedent: **fail-closed safety tightenings may ship at patch level.** The project versions the safety contract's strength; making a guarantee stricter is a fix, and the `CHANGELOG.md` entry carries the breaking-change notice for agent callers. Agents do not reason from version numbers — the guides they load at runtime ship in the same artifact as the schemas, so guide/server consistency is independent of the number chosen. Revisit only if external integrators are known to pin versions.
>
> **Release sizing (open-questions Q15, resolved 2026-07-10: Option C).** v2.3.3 ships as a **single release containing every phase of this PRD** — both tracks and all of D5–D14. The Option A split (model-facing repairs first, execution-side guarantees in a later v2.4.0) was declined: one release cycle, one contract-doc/guide sync pass, no renumbering churn, and Q5 policy continuity. The reviewability risk this concentrates is carried by the mitigations already in the risk table (per-phase commits in dependency order under the Phase 3 type gate; rebuild diffs).

## The problem

**The bug.** `figma_plugin/tsconfig.json` declares:

```json
"typeRoots": ["../../node_modules/@figma"]
```

The tsconfig lives at `figma_plugin/tsconfig.json`, so `../../node_modules` resolves to the **parent of the repository** (`<repo>/../node_modules`), which does not exist. The repo's actual dependency tree is at `<repo>/node_modules` (one level up from `figma_plugin/`, i.e. `../node_modules`). As a result `@figma/plugin-typings` is **never loaded**, and every plugin ambient global is unresolved.

**Consequences.**

- **No type safety on the most safety-critical code in the project.** The plugin dispatcher (`figma_plugin/src/main.ts`) and handlers enforce the entire safety contract (scope, name verification, locked/instance guards, batch atomicity). Today a wrong Figma API call, a typo'd property, or a bad narrowing in that code is caught only at runtime (or live testing), never by `tsc`.
- **Plugin-wide spurious IDE errors.** `tsserver` reports the same unresolved globals, so contributors see red squiggles on `figma`, `console`, `setTimeout`, etc. across every plugin file — training the team to ignore IDE diagnostics on exactly the code where they matter most.
- **It is invisible to CI.** The plugin is bundled with **esbuild** (`figma_plugin/build.js`), which performs no type-checking, and there is **no `tsc` step** for the plugin anywhere in `package.json`, `figma_plugin/build.js`, or `.github/workflows/ci.yml`. So nothing surfaces the breakage.

**Not a runtime bug.** The shipped plugin works — the globals (`figma`, `console`, `setTimeout`, `clearTimeout`, `TextDecoder`, …) all exist in the Figma plugin sandbox at runtime, and esbuild bundles the source unchanged. This is a **lost safety net**, not a live defect. The v2.3.2 live testing confirms the affected code paths behave correctly.

## Decisions

> [!NOTE]
> **D1 — Load the Figma typings via `types`, not `typeRoots`; do not add `dom`.** Replace the broken `typeRoots` with `"types": ["@figma/plugin-typings"]`. Keep `lib: ["es2018"]` (no `dom` — it redeclares globals the Figma typings own). With the exact imported shared file included, this configuration loads the typings and reports the 10 residual errors triaged below.

> [!NOTE]
> **D2 — Fix the residual 10, do not suppress them.** The 10 remaining errors are real type gaps, not noise. Fix each at the source (narrowing, casts, module resolution, the shared schema signature, and one ambient global) rather than blanket-suppressing with `// @ts-nocheck` or loosening `strict`. `strict` stays on. See the triage table.

> [!NOTE]
> **D3 — Add a CI type-check gate, but only after the residual is zero.** Add `check:types:plugin` (`tsc --noEmit -p figma_plugin/tsconfig.json`) to `package.json` and wire it into CI so this regression cannot recur. It must be added **only after D1/D2 bring the error count to 0** — or CI goes red on introduction. The sequencing is by condition, not position: in the phased plan the gate lands as Phase 3, ahead of the Track 2 handler edits (Phases 4–11), so those land under its protection *(wording clarified per open-questions Q6, resolved 2026-07-09: Option A — the original "added last" predates Track 2)*. The plugin build stays esbuild (fast, no type-check); the gate is a separate, additive check.

> [!NOTE]
> **D4 — Scope guard: plugin program only.** This release fixes the plugin tsconfig and the source files in that TypeScript program, including the imported shared type module. It does **not** re-audit the MCP-server tsconfig (`./tsconfig.json`), refactor beyond the 10 residual fixes and the separately ratified Rev 20 suppression-hygiene cleanup, or change runtime behavior in Track 1. If fixing a residual error would require a behavior change, stop and escalate rather than silently altering a live-verified code path.

### The problems (all verified in code and live)

**Gap 1 — design-system updates skip right-object verification.** Node writes require ID + current name; variable and style *updates* do not.

- `variable_manage` / `UPDATE_VARIABLE` checks `currentVariableName` **only when supplied** (`figma_plugin/handlers/variableHandlers.ts:1032`); the schema marks it optional (`src/mcp_server/tools/variable.ts:115`). Live-verified: an ID-only value update mutates the variable with no verification; a wrong name is refused only because it was volunteered.
- `style_manage` with `styleId` has **no** current-name verification at all (`figma_plugin/handlers/styleHandlers.ts:13–23`), and its **required** `name` param is applied as the *new* name on every update (`styleHandlers.ts:47`). Live-verified: an update against a stale/mistaken ID both mutates the wrong style **and renames it** to the caller's wrong belief — destroying the evidence of what it was called.
- `variable_manage` / `CREATE_VARIABLE` accepts `collectionId` with no `collectionName` verification (`variableHandlers.ts:963`), unlike `variable_delete`, which requires and verifies it.
- `SAFETY.md` **G2** claims name verification covers "every write tool" — contradicted by its own Part B matrix rows for `variable_manage` and `style_manage`, and by the live behavior above.
- `UPDATE_VARIABLE` mutates before it finishes validating: `name`, `description`, and `scopes` are applied (`variableHandlers.ts:1040–1051`) before a missing `modeId` for a supplied `value` is discovered (`:1053`) — a predictable late failure leaves a half-updated global token. The style path has the same shape: `name`/properties are applied before later variable bindings resolve, and the rollback at `styleHandlers.ts:130–135` removes only freshly *created* styles; it never restores an updated one.
- `CREATE_VARIABLE` accepts omitted `scopes` (`if (scopes !== undefined)`, `variableHandlers.ts:990`), although the tool description says scopes must always be set explicitly on create — an underspecified global asset is created silently.
- The verification error at `variableHandlers.ts:1033` labels the stored name "Expected" and the caller's value "got" — arguable rather than wrong, but recovery should not depend on interpreting operand order.

**Gap 3 — create-tool schemas contradict the runtime contract.** `parentNodeName` is `.optional()` in the `create_shape`/`create_frame`/`create_text`/`create_svg`/`create_instance` schemas (`src/mcp_server/tools/create.ts`), while the runtime fails closed when it is absent (`verifyParentName`, `figma_plugin/src/main.ts:151`) and `SAFETY.md` A3/A4 already document it as required. Live-verified: omitting it is refused with `PARENT_NAME_MISMATCH` — a safe but avoidable failure, made worse by the error text ("recheck to ensure correct parentId is passed in"), which misdirects the agent toward the parent *ID* when the parent *name* was simply missing.

**Gap 5 — `node_delete` reports success on partial failure.** `deleteMultipleNodes` returns `success: successCount > 0` (`figma_plugin/handlers/nodeModifiers.ts:294`). Live-verified: a batch that deleted 1 of 2 items returned `{"success":true,"nodesDeleted":1,"nodesFailed":1}`. The other three batch aggregators (`text_set_content`, `annotation_set`, `instance_set_overrides`) already require `failureCount === 0`.

**Gap 6 — `annotation_set`'s advertised contract cannot reach its handler's success path.** The registered item schema (`src/mcp_server/tools/annotation.ts:42–49`) requires `categoryId`, exposes `annotationId` and `status`, shapes `properties` as a record — and omits `labelMarkdown`, the one field the handler requires (`annotationHandlers.ts:142–144`). The handler ignores `annotationId`/`status` entirely, and Figma's pinned `Annotation` type supports neither. Because strictness is not recursive (Gap 7), a caller who supplies `labelMarkdown` anyway has it silently stripped before dispatch. Net: **no conforming MCP call can ever create an annotation** — the tool is advertised, marked `idempotentHint: true` (it appends; append is not idempotent), and unusable. The read side drifts too: `annotation_list`'s registered output advertises `annotations` while the page-mode handler returns `annotatedNodes` (`annotationHandlers.ts:48`), masked by `looseOutput`.

**Gap 7 — the batch contract has holes the Q7 resolution missed.** Corrections to Rev 9, all verified in code:

- **Empty batches pass the schemas.** No batch array has `.min(1)`; `[]` is accepted at the boundary and produces a different ad-hoc failure shape per tool. Rev 9's claim that "zero-item batches are unreachable through the schemas" was **false**.
- **Stop-on-first omits rows.** `setMultipleTextContents` `break`s on first failure (`textHandlers.ts:108–169`) without emitting rows for unattempted items — a caller cannot distinguish "failed" from "never attempted".
- **Duplicate targets are accepted.** The live duplicate-delete probe (4n79, 2026-07-09) passed prevalidation twice for the same node and manufactured a spurious failure row.
- **Dispatcher prevalidation throws.** Per-item prevalidation failures are thrown errors, not envelopes, so "`status` on every return path" cannot be delivered by the aggregators alone — the contract must define its layers explicitly.
- **Output schemas drift from handlers.** `node_delete` advertises `deletedCount` (`node.ts:181`) but returns `nodesDeleted`/`nodesFailed`; `text_set_content` advertises `count` (`text.ts:25`) but returns `replacementsApplied`/`replacementsFailed`. `looseOutput` hides the drift.
- **Strictness is shallow.** The central wrapper's `.strict()` applies only to the top-level object (`tools/index.ts:31–40`); nested objects silently strip unknown keys — exactly the intent loss the wrapper's own comment says it exists to prevent.

**Gap 8 — implicit-parent Figma APIs place nodes outside the verified destination.** `node_flatten` calls `figma.flatten([node])` with no parent (`nodeModifiers.ts:505`); the API defaults the result to `figma.currentPage`, so a nested flatten jumps to page root — outside the editable subtree in node scope. `create_component_set` combines on the containing page and reparents only afterward (`componentHandlers.ts:962, 984–985`), so a no-parent call leaves the set at page level. The ordinary creators construct on `currentPage` first and append later — `create_shape` creates at `nodeCreators.ts:74–96` and appends at `:146` with fallible setters in between, and `create_text` creates (`:363`), **awaits fonts** (`:369`), and only then appends (`:396`), sitting observably outside its destination across an async boundary. Clone paths append only after `clone()` (`:454`), which likewise defaults to `currentPage`.

**Gap 9 (connectors) — verified 2026-07-10 (source + live channel `90vr`); the product decision remains open (Q13).** All five reported defects are confirmed: the default-template auto-adoption scans `figma.currentPage` with no scope check (`connectorHandlers.ts:245`, and silently again inside `createConnections` at `:461`); the default is cached in plugin-wide `clientStorage` under a key with no document scoping (`:199, :253, :457`), so a stale ID can resolve to an arbitrary same-ID node in another file (only the type check stands between that and a wrong template); `connectorId` has no name-verification field in schema or handler (existence + type only, `:188–196`); per-item failures do not clean up — a cursor created for a start endpoint leaks if the end endpoint fails (`:493–513`), a failed SVG-cursor append leaks the import (`:349, :398–401`), and the catch path removes nothing (`:603–621`); and the aggregate returns `success: true` unconditionally with `count = results.length`, which counts **error rows as connections** (`:635–639`). Live on `90vr` (Design file): the no-default flow, the type-only template validation, and the bootstrap dead-end ("copy a connector from FigJam manually") all reproduced; clone/cursor leak and mixed-result probes are blocked pending a FigJam-pasted connector fixture and remain source-verified only.

**Gap 10 — nothing binds a command to the plugin peer that will execute it.** The socket broadcasts every message to all other peers in the channel (`src/socket.ts:139–155`); joins carry no client type or peer identity; the join payload carries no plugin version (verified live on 4n79 — `channel_join` returns none); and `resetChannel()` clears only a local variable without leaving the socket room (`figma-client.ts:295–297`). With two plugins in one channel, one can answer the handshake and a different one can execute a later write, and neither the server nor the user can tell.

**Gap 11 — errors are flattened to strings and page loads are all-or-nothing.** The dispatcher catch converts every plugin failure to a string (`describeError`, `main.ts:319–324`) and `figma-client.ts` reconstructs plain `Error`s, so stable failure codes cannot survive to the MCP boundary. Multi-page reads have no per-page recovery: `getPagesInfo` awaits `loadAsync()` per page inside its loop (`nodeReaders.ts`), so one unloadable page fails the entire command with Figma's raw error. Destructive document-wide scans (`variable_delete`) currently fail closed only *by accident* — a page-load throw happens to abort the command — which must become an explicit, tested contract rather than a side effect.

### Decisions

> [!NOTE]
> **D5 — Bring design-system updates up to the node-write standard (Gap 1).** Fail closed on a missing or mismatched current name, exactly like `verifyNodeName`:
> - `UPDATE_VARIABLE`: `currentVariableName` becomes **required** — in the `variable_manage` schema and in the handler (absent ⇒ reject, mismatch ⇒ reject, before any mutation).
> - `CREATE_VARIABLE`: new **required** `collectionName`, verified against the resolved collection's name before `createVariable` (same pattern as `variable_delete`).
> - `style_manage` with `styleId`: new **required** `currentStyleName`, verified against the resolved style's name before any mutation.
> - `style_manage` `name` becomes **optional at the schema level**: the handler enforces it on create; on update it renames only when explicitly provided. This removes the accidental-rename side effect — a properties-only update no longer has to pass (and therefore overwrite) the name.
> - `scopes` becomes **required on `CREATE_VARIABLE`** (schema refinement + handler defense in depth). Explicitly supplied empty scopes remain the caller's deliberate choice; omission is rejected.
> - **Validate the complete plan before the first write (Rev 11, Gap 1 late-mutation fix).** On `UPDATE_VARIABLE`, a supplied `value` requires a valid `modeId` *before* `name`/`description`/`scopes` are touched; on `style_manage` updates, resolve every requested variable binding before applying `name` or properties. Predictable failures return with zero mutation; an unexpected mid-update failure is reported explicitly as partial via a D9 error — never as a clean failure.
> - **Pre-check scope (open-questions Q17, resolved 2026-07-18: Option B).** "The complete plan" means everything one read or one property check can confirm. Two checks join the letter above, both before any mutation: an alias `value` (`type: "VARIABLE_ALIAS"`) resolves its target variable via `getVariableByIdAsync` — a dangling target is a predictable failure and must mutate nothing; and a PAINT-style `bindVariables` request verifies the style has paints to bind before `name`/`description`/`properties` apply — the implementation-review finding was that this refusal fires only after those mutations. Deep value-type validation is **rejected**: simulating Figma's coercion rules invites refusing calls Figma would accept, and drifts as the plugin API evolves. The boundary rule, recorded for future tools: *pre-validate what one read can confirm; disclose what only execution can reveal* (disclosure shape: the Q18 bullet below).

The fix has three parts:
> - **The schema enumerates the union per variant.** `effects[]` becomes a `discriminatedUnion` over the seven pinned `type` literals (`DROP_SHADOW`, `INNER_SHADOW`, `LAYER_BLUR`, `BACKGROUND_BLUR`, `NOISE`, `TEXTURE`, `GLASS`), each with its own field list, plus the secondary discriminators the typings define — `blurType` (with the PROGRESSIVE ramp gated on it) and `noiseType` (with `secondaryColor` gated to DUOTONE and `opacity` to MULTITONE). Both effect surfaces share the exact `BlendMode` enum. Shadow and blur radii are non-negative. Live-confirmed GLASS bounds are also enforced at the boundary: `radius >= 0`, and `lightIntensity`, `refraction`, and `dispersion` each lie in `0..1`; `depth` is deliberately not constrained to the pinned typings' documented minimum because Figma accepted `depth: 0` on channel `o4g6`.
> - **The enumeration is pinned, not hand-maintained.** Mechanical parity tests resolve both the `Effect` union and `BlendMode` literals in `plugin-api-standalone.d.ts` — following type aliases (`BlurEffect`, `NoiseEffect`) and `extends` bases (`BlurEffectNormal` → `BlurEffectBase`) — and fail if either inventory drifts. > - **The handler stops discarding.** `normalizeEffects` filled defaults by *rebuilding* each effect from a named field list, so it dropped everything it did not name — `blurType` and the PROGRESSIVE ramp (silently downgrading a progressive blur to a normal one) and every field of the NOISE/TEXTURE/GLASS variants. It now applies defaults **on top of** the caller's object. A schema that declares a field the handler discards is the same defect one level down, so this part is not optional. A `type` outside the pinned union — reachable only from a client that bypassed the schema — is still forwarded untouched rather than having fields injected into a shape we cannot know.

The residual is therefore accepted here, recorded in `style.ts`, and closed by the pin bump — with the parity test guaranteeing the bump cannot happen silently.

> **D7/D5 addendum — the partial-mutation vocabulary is not limited to text and instances (open-questions Q32, resolved 2026-07-25: Option A).** Q9 named text content and instance overrides because those were what the review found; Q18 then generalized the *convention* ("one convention across batch rows and single-object tools"). Three further mutate-then-fail paths adopt it:
> - **`annotation_set` rows.** An append that commits and then throws carries `partialMutation: true`, a `whatChanged` statement, and `before: {annotationCount}`. Only positive proof that the source is live, every original child is back, and the component is empty authorizes removal; a failure whose confirmed cleanup succeeds still throws untouched.
> - **`create_component_set`.** A failed rename/combine inspects placement **before** any recovery name write and compares both names and parent locations. Ordinary live members restore their original names best-effort. Members already moved into a surviving `COMPONENT_SET` retain or best-effort confirm their computed variant names; a changed parent whose type is unreadable never authorizes an original-name write. Evidence separates applied/restored/unrestored/removed/unknown-removal members, reparented and unverified placement, surviving sets, and retained/unconfirmed variant members. A post-combine failure (the set exists and members are already valid variants; renaming them back would corrupt the set, so D5's no-transaction posture forbids rollback) uses guarded identity/name/location snapshots, verifies the set's actual parent against the required destination, and discloses those snapshots. > **D13 — Bind one plugin peer to one MCP session (Gap 10).** The minimal peer-binding core, deliberately without the follow-up review's protocol-digest machinery: the plugin's join message carries `clientType: "plugin"` and its build version; the socket assigns each connection a random `peerId`, reserves a channel as **exactly one plugin peer plus one MCP session**, and routes commands and responses only within that bound pair (responses are correlated by peer; a response from any other peer is ignored). The three agent-reachable codes are unaffected.
> **Join-attempt recovery boundary (Change 6, Rev 58).** A connection owns one reservation, so replacing a healthy binding first releases it. The exact released channel is attempt metadata across both registered-tool legs: the socket join and the following scope-payload read. Cross-channel and same-channel replacement both qualify; an already-invalidated binding does not. `figma-client` records locally decided predecessor evidence separately from public details, and `channel.ts` supplies authoritative context on both legs even when no predecessor exists. A failure preserves the originating code/message/details and adds top-level `releasedChannel` only when that context says one was actually released; cleanup retains that value for the following `CHANNEL_NOT_BOUND`, and success never exposes the internal metadata. An explicit `UNKNOWN_ERROR` remains an authored structured code rather than triggering a generic double prefix. Plain-record details without a reserved-key collision gain the recovery field directly, absent details become the one-field record when evidence exists, and non-record or colliding details survive under `originDetails`. Origin details can never fabricate predecessor state. `resetChannel` clears local state before awaiting leave. If leave acknowledgement cannot be confirmed it closes the MCP bridge socket as final cleanup; a `leave-previous-channel` failure therefore says the requested join was never sent and instructs reconnect plus an explicit join, never that the previous channel remains held.
> **Pending-route lifetime (Change 6, Rev 58).** Every pair-correlated route has an inactivity timer. Progress refreshes its timestamp and re-arms the timer, so a communicative long command remains live. Terminal delivery, request-ID replacement, pair detach, and server close remove the route and cancel its timer. Timer expiry works while the channel is otherwise idle, and every arriving plugin frame rechecks the boundary so delayed timer scheduling cannot forward expired progress or a terminal reply. Dispatch-time pruning is retained only as a backstop.

### Compatibility posture

**Origin split correction (Change 5 P9-F3; synchronized by Change 6).** The Rev 11/initial-Q27 transport wording in D9 is historical and is superseded at the origin boundary: the four D13 admission codes are raised only by the socket's `CHANNEL_REFUSALS`; `CHANNEL_NOT_BOUND` is raised only by the MCP client's `CLIENT_REFUSALS`; neither travels from the plugin dispatcher or belongs in the plugin bundle. The plugin `REFUSALS` registry contains only plugin-origin D5/D6/D10 codes and the six Phase 10–11 operational entries. “Every coded refusal originates from a central registry” therefore means exactly one registry at the layer that can raise the code, not a plugin/server parity mirror. The ratified inventory is eleven operational codes plus ten verification codes, for twenty-one total plus `UNKNOWN_ERROR`.

These are **deliberate breaking tightenings** for agent callers, not regressions: a call that previously performed an *unverified* global write now fails with a structured error naming the missing field, and the updated guides tell the agent how to recover (read the current name, pass it back verbatim). Gap 3's schema change is not behaviorally breaking — calls omitting `parentNodeName` already failed at runtime; they now fail earlier with a better contract. The `CHANGELOG.md` entry must call out all newly required fields and the new batch `status` field explicitly.

Rev 46 records one breaking change the earlier revisions missed: **`annotation_list`'s node mode returns the grouped `annotatedNodes` shape.** Gap 6 described the drift as page-mode-only, so the repair was framed as a schema correction — but D10's "preserving node ownership in **both** page and node modes" is a *handler* change to the mode that previously matched its advertised schema. Node mode used to return `{nodeId, name, annotations: [{nodeId, annotation}]}` (a flat list of annotation objects tagged with their owner); it now returns `{annotatedNodes: [{nodeId, name, annotations}]}`, the same grouped shape as page mode. A reader of the old flat list breaks. This is the right shape — one output contract across both modes, ownership preserved — but it is breaking, and the CHANGELOG must carry a before/after example.

Rev 47 adds one more: **`style_manage`'s `effects[]` is now strict per variant.** A call carrying a key the pinned `Effect` union does not define — inside an effect object — is rejected instead of accepted-and-discarded. Nothing that previously reached Figma stops reaching it: the discarded keys never did. Progressive blurs and NOISE/TEXTURE/GLASS effects newly work end to end, because the handler no longer rebuilds effects from a four-type field list. The CHANGELOG carries a before/after example.

Rev 11 widens the breaking surface: `annotation_set`'s field set changes (`labelMarkdown` required; `annotationId`/`status` removed; `categoryId` optional-but-verified) — a strict correction, since no conforming call could previously succeed at all; `create_component_set` requires an explicit parent; recursive strictness rejects nested unknown keys that were previously stripped silently; batch inputs require at least one item and refuse duplicates; the batch handlers drop their tool-specific count fields (`nodesDeleted`/`nodesFailed`, `replacementsApplied`/`replacementsFailed`, `annotationsApplied`/`annotationsFailed`, the duplicate `totalCount`, and the `total*` totals) in favor of the shared envelope counts (`requestedCount`/`succeededCount`/`failedCount`/`skippedCount`), removing the advertised-but-absent drift rather than aliasing it (Q26); the four batch tools' per-item rows converge on one vocabulary (`nodeId`/`status`/`error`), which renames `instance_set_overrides`' previous `instanceId`/`instanceName`/`message` row keys (Q25 — `instanceName` may remain as an additive field); and `channel_join` gains version/peer fields and can newly refuse an empty channel, a second MCP session, or a known version mismatch. A second plugin is instead refused `PLUGIN_PEER_AMBIGUOUS` at that plugin's own join and never reaches `channel_join`. Per Q13, `create_connection` becomes creation-only with a required, name-verified template on every call — the default-template/check modes and the cache are removed, and the structured `CONNECTOR_TEMPLATE_REQUIRED` error teaches the bootstrap. The CHANGELOG lists each with a before/after example.

Revs 51–54 make four strict corrections explicit. First, annotation result counts become nullable verified observations and add required `beforeCountVerified`/`afterCountVerified`; an unreadable post-attempt state adds `outcomeUnknown:true` rather than fabricating a number. Second, `create_text.fontSize` rejects values below 1 and `fontWeight` accepts only 100–900 in increments of 100; previously accepted off-grid values could be silently misapplied. Third, Rev 52 supersedes Rev 51's attempted empty-name preservation: because Figma normalizes explicit empty layer names, `name:""` / `componentSetName:""` is rejected before mutation, while omission retains the prior default. Fourth, Rev 54 applies that truthfulness rule to every action that assigns a user-visible name and makes recovery field-specific; it does not change unrelated lookup semantics. These changes reject or more precisely describe calls that could not be executed and reported truthfully.

Rev 56 records the break the peer-binding work missed (Change 5, P9-D1): **the socket now refuses any join frame that does not declare `clientType`.** Rev 11's entry listed only that "`channel_join` gains version/peer fields and can newly refuse empty, ambiguous, or version-mismatched channels", which understates it — the plugin/server handshake itself is now mandatory and versioned, so an **already-installed pre-2.3.3 plugin build cannot connect to a 2.3.3 socket at all**. It receives `{"type":"error","message":"clientType must be exactly 'plugin' or 'mcp'."}`, closes its socket, and surfaces the text in the plugin UI. This is the intended hard cutover (Q8) rather than a regression — the peer binding cannot be enforced against a peer that will not identify itself — but it means upgrading the server *requires* rebuilding and reinstalling the plugin, which the CHANGELOG must state plainly rather than leaving a user to discover through a failed connect. `check:versions`/`check:plugin` already couple the two artifacts at release time, so a released pair is never skewed; the exposure is a user running a new server against an old installed plugin.

Rev 20 adds one **additive** repair: `create_instance` gains the `componentId` response field its handler intended to return but never delivered — `InstanceNode.componentId` does not exist at runtime, so the value was `undefined` and the key was dropped in serialization (live-verified 2026-07-17, channel `p28j`). No caller had received the field, so nothing broke. Rev 50 closes the inverse contract drift found after that repair: the handler now returns `component.id`, and the advertised output schema explicitly declares `componentId`; an official-client `tools/list` assertion prevents `looseOutput` from masking the field again.

**Hard cutover confirmed (open-questions Q8, resolved 2026-07-09: Option A).** There is no warn-only transitional release. A warning attached to a successful result is precisely the signal agents are known to ignore (Gap 5's live lesson), so a grace period would keep the unverified-write path open while buying no real migration safety. With the D5 dual descriptions preventing most first-call omissions and the D9 self-recovering errors, the entire migration cost is one recovery round trip per affected agent — for a safety fix, a grace period is a period in which the fix is off.

## Risks & mitigations

| Risk | Likelihood | Mitigation |
| :- | :- | :- |
| A residual fix accidentally changes runtime behavior on a live-verified path | Low | D4 stop-and-escalate rule; `check:plugin` rebuild-diff catches any unexpected emitted-JS change; the fixes are types/casts/config only |
| Fixing `shared/nodeTypes.js` resolution un-masks further errors in `shared/` | Low–Med | Include only the imported `../src/shared/nodeTypes.ts` file, triage its surfaced error explicitly, and do not make the entire shared directory a plugin root |
| `TextDecoder` ambient declaration drifts from a future `@figma/plugin-typings` that adds it | Low | Prefer the typings if a version provides it; otherwise a one-line ambient `declare` with a comment pointing here |
| Turning on the CI gate blocks unrelated PRs if the residual isn't truly zero | Low | D3 sequencing — gate added only after Phase 2 reaches 0; prove-red/prove-green before wiring into CI |
| Existing agent workflows break on the newly required fields (D5/D6) | Med | Intended fail-closed tightening (v2.2.0 precedent); structured errors name the missing field; guides/error-playbook updated in the same change (D8); `CHANGELOG.md` calls out every new requirement |
| `SAFETY.md` matrix and `safetyContract.test.ts` drift apart during the change | Low | D8 same-change rule; the bidirectional mechanical diff fails CI on any mismatch |
| New `status` field breaks outputSchema validation on older clients | Low | Additive only; `looseOutput` catchall accepts extra keys by design |
| Agents keying on `node_delete`'s old lenient `success` misread the corrected value | Low | The corrected value is the safe direction (false where formerly true); descriptions and guides explain `status` |
| Recursive strictness rejects nested fields older clients had silently ignored | Med | Desired correction of silent intent loss; the MCP validation error names the exact path; CHANGELOG migration notes list removed/renamed nested fields |
| Peer binding changes the socket's broadcast behavior for existing setups | Med | One-to-one pair table with per-peer response correlation; explicit leave/unbind; integration tests cover two-plugin, two-client, and disconnect cases |
| Rev 11 scope growth makes the release harder to review | Med | The follow-up review's heavy machinery is explicitly deferred (see non-goals); remaining phases land in dependency order under the Phase 3 type gate with phase-scoped commits/diffs. Rev 30A records the Phase 1–2 exception: one combined commit, one immediate missing-file follow-up, and unrelated documentation churn preserved in history. |
| Removing the connector default/cache breaks existing default-template workflows | Low–Med | The default only saved re-passing an ID the caller had to discover once anyway; `CONNECTOR_TEMPLATE_REQUIRED` teaches the explicit flow; CHANGELOG migration example |
