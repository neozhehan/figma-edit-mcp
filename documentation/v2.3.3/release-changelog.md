### Why the guard had to change shape

Q27 forbids the plugin bundle importing `src/shared` at runtime, so the producer and the consumer **cannot share a constant**. That is not incidental; it is the precise reason C9-F1 was possible at all, and it means a test is the only guard available. The previous guard could not be that test, because `connectHandlers.ts` chains to `main.js`, whose import side effects the suite deliberately avoids — which is why the producer side was asserted by reading source text in the first place.

The fix removes that constraint instead of working around it. The failure shape moves into `toConnectPayloadError()` in `utils/pageLoad.ts`, a module with no `main.js` chain that tests already import freely. The key is now decided in exactly one place, the handler delegates to it, and a test can drive the real producer shape through the real registered consumer.

### Exact implementation contract

- **One definition of the private connect-payload error shape.** `toConnectPayloadError(StructuredPageError)` returns `{errorCode, errorMessage, details?}`, omitting `details` when absent so the existing "no details means no `errorDetails` key" contract is preserved. `channel_join` alone renames `details` to public `errorDetails`.
- **The handler delegates rather than rebuilds.** `connectHandlers.ts` returns the projector's result directly. The source assertion now pins *delegation* and forbids rebuilding the envelope inline, which is a structural property; the field names themselves are proven behaviourally.
- **The seam is tested end to end.** Two regressions drive a real `PageLoadCoordinator` failure — a rejected load and a bounded timeout — through the real projector into the real registered `join_channel` callback, asserting `errorDetails.pageId`, `errorDetails.cause`, and `errorDetails.timeoutMs` arrive intact.

### Exact implementation contract

- **A partial read names what it dropped.** `node_info` distinguishes three outcomes for a requested ID: returned in `nodes`; absent from the document and listed in `missingNodeIds`; or present but unreadable and listed in `pageFailedNodes` with its `pageId`. That `pageId` is the join key into `coverage.pageErrors`, so the reason and its recovery are one lookup away with no second call. `page_info` applies the same principle at page granularity: `missingPageIds` is every requested ID absent from `pages`, whatever the cause.
- **Load failure and read failure are different causes with different recovery.** `PAGE_LOAD_FAILED` covers a page that would not resolve or load and tells the caller to retry. `PAGE_SCAN_FAILED` covers a page that loaded and then failed while being read, states that retrying the identical call usually reproduces it, and directs the caller to narrow the request. Both keep the originating cause in `details.cause`.
- **`coverage` distinguishes "clean" from "untouched".** `pagesAttempted` is required on every coverage object and counts the distinct pages a call tried to resolve, load, or read. `complete: true, pagesAttempted: 0` means no page access was required and is never evidence about the document.
- **The coverage invariant is advertised, not only parsed.** `pageCoverage` is a two-branch union (`complete: true` with `maxItems: 0`, `complete: false` with `minItems: 1`), so `complete === (pageErrors.length === 0)` survives into the emitted JSON Schema instead of being erased with the refinement.
- **One `error` type across the tool surface.** Top-level `error` is the D9 `{code, message, details?}` envelope on every tool without exception. `variable_delete`'s in-use refusal is the coded `VARIABLE_IN_USE`, carrying `details.variablesInUse` in its existing shape and a message that names the read tool per consumer kind, states that nothing was deleted, and says to retry the same call after rebinding. Every consumer line in that message carries its ID, because names collide (C8-F9), and the recovery sentence begins on its own line after the listing.
- **Every page load in the plugin is bounded.** The scope-payload load on `channel_join`'s second leg shares the coordinator and its 10-second per-page bound and reports ratified codes; `DOCUMENT_LOAD_FAILED` is retired. The bound remains per page: a command touching N pages is still N × the per-page bound, which Q12 accepted when it rejected total deadlines.
- **The fail-closed destructive gate is unchanged in strength.** `variable_delete` still loads every document page and still refuses with `DOCUMENT_SCAN_INCOMPLETE` before any `remove()` when coverage is incomplete, in variable mode, collection mode, and apparently-empty-collection mode. Only the traversal that searches for members of an empty set is skipped.

The current cleanup regression ([`v2.3.3.phase8.test.ts:684`](../../src/mcp_server/tests/unit/figma_plugin/v2.3.3.phase8.test.ts#L684)) checks logging and error precedence, not the survivor's placement or client-visible disclosure.

**Required closure.** Treat removal outcome as data on every creator path: preserve the initiating error, inspect whether the node actually disappeared, and attach `partialMutation`, survivor ID, and observed location whenever it did not. Regress append/configuration failure crossed with cleanup returning `false` or throwing through the registered command boundary.

#### F78-03 — component-set restoration failure masks and under-reports mutation

**Evidence.** `create_component_set` renames every source component before combining, then restores names with unguarded setters in its catch ([`componentHandlers.ts:1294`](../../figma_plugin/handlers/componentHandlers.ts#L1294)). A deterministic combine failure plus restoration-setter failure replaced the combine error, stopped later restoration, and left variant names applied without partial-mutation details. Existing tests cover successful restoration and the removed-member skip, not a present node whose restoration setter throws.

**Required closure.** Restore each member best-effort, preserve the initiating error, and disclose applied, restored, and unrestored names. Add a multi-member regression in which an early restoration setter fails while later members are still attempted.

#### F78-04 — `annotation_list` violates its node-and-subtree contract

**Evidence.** The registered description promises a node “and subtree” ([`annotation.ts:115`](../../src/mcp_server/tools/annotation.ts#L115)), but node mode rejects the root when the root itself lacks `annotations` before the descendant traversal begins ([`annotationHandlers.ts:109`](../../figma_plugin/handlers/annotationHandlers.ts#L109)). Live on `o4g6`, a `GROUP` root containing an annotated rectangle returned `UNKNOWN_ERROR: Node type GROUP does not support annotations` instead of the descendant.

**Required closure.** Permit any traversable root and test the annotation mixin inside the recursive collector. Regress at least a `GROUP` root with an annotated descendant through the registered callback and live tool.

#### F78-05 — `node_set_effects` silently loses cross-variant intent

**Evidence.** `node_set_effects` uses one shared object schema and allows `showShadowBehindNode` for every effect type ([`node.ts:633`](../../src/mcp_server/tools/node.ts#L633)). The plugin then deletes that field from `INNER_SHADOW` ([`stylingHandlers.ts:336`](../../figma_plugin/handlers/stylingHandlers.ts#L336)). Live on `o4g6`, the schema accepted that combination and the successful result silently omitted the requested field.

**Required closure.** Give `node_set_effects` a strict per-variant discriminated union, including a `DROP_SHADOW`-only `showShadowBehindNode`, and add negative schema-boundary and live regressions.

#### F78-06 — effect schemas omit live runtime numeric bounds

**Evidence.** Shadow/blur radii and GLASS controls are unconstrained `z.number()` fields in [`style.ts:103`](../../src/mcp_server/tools/style.ts#L103), [`style.ts:126`](../../src/mcp_server/tools/style.ts#L126), and [`style.ts:216`](../../src/mcp_server/tools/style.ts#L216). Live calls passed schema validation and were then rejected by Figma for `LAYER_BLUR.radius: -1`, `GLASS.radius: -1`, and `GLASS.lightIntensity`, `refraction`, and `dispersion` set to `2`.

**Required closure.** Constrain the live-confirmed ranges at the MCP boundary: the tested radii are non-negative, and `lightIntensity`, `refraction`, and `dispersion` are within `0..1`. Add schema tests using the exact rejected values and live-valid boundary values.

#### F78-07 — `create_instance.componentId` is not advertised

**Evidence.** The handler returns the resolved component ID at [`componentHandlers.ts:308`](../../figma_plugin/handlers/componentHandlers.ts#L308), and live `o4g6` calls returned it correctly. The registered output schema declares only `id`, `name`, and `parentId` ([`create.ts:227`](../../src/mcp_server/tools/create.ts#L227)). The output test even supplies `componentId` ([`outputSchema.test.ts:332`](../../src/mcp_server/tests/unit/tools/outputSchema.test.ts#L332)), but `looseOutput` accepts it as an undeclared extra and masks the drift.

**Required closure.** Declare and describe `componentId` in the emitted output schema, then assert its presence in `tools/list` rather than only safe-parsing a loose result.

#### F78-08 — removed component-set members were treated as clean recovery

**Evidence.** Re-auditing the new best-effort restoration exposed a pre-existing adverse path: when `combineAsVariants` removes a source component and then throws, recovery skipped that member because `removed === true`. If every still-present member's name restored, the handler rethrew the combine error without `partialMutation`, even though a pre-existing component had disappeared. The Phase 8 removed-member regression asserted only that later names restored.

**Required closure.** Preserve the combine error, continue restoring live members, classify removed members separately, and disclose the operation as partial whenever `removedComponents` is non-empty. The regression must assert the removed member plus the applied/restored/unrestored buckets.

#### F78-09 — unknown recovery state could authorize destructive cleanup

**Evidence.** The first remediation read `sourceFrame.removed` and each original child's `parent` through a fallback that converted an unreadable getter into `false`. Recovery could therefore conclude that the source was live and that the component owned no original children, remove the new component, and report a clean failure even though the component might still contain pre-existing user content.

**Required closure.** Treat source removal and child ownership as explicit live/removed/unknown states. Remove the component only after positive proof that the source is live, every original child is back on it, and the component is empty. Unknown, relocated, or still-owned children must keep the component and appear in partial-mutation evidence.

#### F78-10 — child restoration stopped after the first failure

**Evidence.** The recovery loop gated every later restoration on one shared `restoredAllChildren` flag. An early setter/insertion failure therefore prevented independent later children from being restored, even when those later moves were safe, and the one-child regression could not reveal the short circuit.

**Required closure.** Attempt every eligible child independently, retain original sibling order around children that never moved, preserve the initiating conversion error, and disclose each failed restoration without suppressing later attempts.

#### F78-11 — failed combine recovery ignored component placement

**Evidence.** `combineAsVariants` may reparent live components into a newly created component set and then throw. The recovery code compared only names and `removed`; if names restored and every component remained live, it rethrew a clean combine error even though the inputs no longer had their original parents and a set survived.

**Required closure.** Snapshot original parent IDs before the first rename. After any failed combine, compare every live component's current parent and include `reparentedComponents` or `unverifiedPlacementComponents` in a partial-mutation error whenever placement did not return to the captured state.

#### F78-12 — post-combine evidence reads could erase mutation truth

**Evidence.** After `combineAsVariants` returned, the handler read `name`, `id`, `parent`, and `children` outside a total recovery/projection boundary. A getter failure could replace a requested-rename error or surface as an ordinary clean failure after the set already existed. The handler also trusted, rather than verified, that the returned set used the requested parent.

**Required closure.** Snapshot the created set's required identity/name/location with guarded reads, verify its actual parent against the verified destination, and reuse those snapshots in every partial error. Treat required-field or location uncertainty as partial; make optional `variantGroupProperties`/child-count reads best-effort warnings that cannot erase a confirmed successful mutation.

#### F78-13 — effect `blendMode` was not schema-bounded

**Evidence.** Shadow and NOISE schemas used `z.string()` for `blendMode`, even though the pinned Figma typings define a closed 19-literal `BlendMode` union. `style_manage` and `node_set_effects` both accepted `NOT_A_BLEND_MODE`, and `normalizeEffects` forwarded it to Figma.

**Required closure.** Reuse one exact `BlendMode` enum across every effect variant, pin its literal inventory to the installed typings, accept every ratified value, and reject an invalid value through both registered effect surfaces.

#### F78-14 — failed-combine recovery could corrupt a surviving component set

**Evidence.** `combineAsVariants` may reparent the inputs into a durable `COMPONENT_SET` and then throw. The first recovery implementation restored every live member's original name before interpreting the new parent, turning valid variant names such as `Size=A` back into ordinary names such as `A` inside the surviving set. Its regression encoded that corrupted outcome. A sibling path treated an unreadable new-parent `type` as permission to perform the same unsafe restoration.

**Required closure.** Inspect placement before any recovery name write. Members confirmed inside a surviving component set retain or best-effort confirm their computed variant names; a changed parent whose type is unreadable blocks original-name restoration. Disclose surviving sets plus retained/unconfirmed variant members, and keep unknown placement partial.

#### F78-15 — explicit empty creator names cannot be preserved

**Evidence.** The first remediation replaced truthiness defaults with presence-sensitive assignments and its stubbed tests expected `""` to survive. The live `2476` matrix disproved that premise across all five surfaces: `create_shape` read back as `Rectangle`, `create_frame` as `Frame`, `create_text` as its text content (`empty-name` in the probe), `create_svg` as `Frame`, and `create_component_set` as `Component`. A separate `node_rename({name:""})` probe also read back as `Rectangle`, demonstrating native Figma normalization rather than stale plugin code.

**Required closure.** Reject an explicitly empty `name` on `create_shape`, `create_frame`, `create_text`, and `create_svg`, and an explicitly empty `componentSetName` on `create_component_set`, at both the MCP schema and plugin defense-in-depth boundaries before any creation, rename, or combine. Omission remains valid and retains each established default. Pin rejection/no-mutation and omission/default behavior across all five surfaces, then repeat those refusals live.

**Resolution.** The five registered MCP schemas now require `minLength:1`, and the plugin independently rejects exact-empty supplied names before any creator or combine call; omission and non-empty whitespace retain their prior meaning. Official-SDK live verification on channel `4mor` passed all five refusals with per-call descendant counts unchanged at 59, then passed all five omission paths with defaults `Rectangle`, `Frame`, `Text`, `Frame`, and `Component 1`. Cleanup deleted the disposable root and restored the 59-descendant baseline.

#### F78-16 — unreadable component removal state was classified as live

**Evidence.** Failed component-set recovery read `component.removed` through a boolean fallback. A throwing or non-boolean getter therefore became `false`, allowing later recovery logic to act as though the pre-existing component were confirmed live and omitting the uncertainty from the partial-mutation evidence.

**Required closure.** Model removal as `live | removed | unknown`. Unknown must never authorize a destructive or otherwise optimistic recovery inference and must be disclosed separately as `unknownRemovalComponents`.

#### F78-17 — survivor location evidence confused unknown with detached

**Evidence.** Ordinary creator cleanup mapped both `node.parent === null` and a throwing `node.parent`/`parent.id` getter to `survivingParentId:null`, then described either case as `detached/null`. The hostile-getter regression pinned the false claim rather than detecting it.

**Required closure.** Carry `survivingParentState: "located" | "detached" | "unknown"` alongside the nullable ID. Only an observed `parent === null` is detached; unreadable parent or ID state is unknown, and recovery prose must say so. Apply the analogous state field to `create_component`.

#### F78-18 — error reporting was not total for hostile thrown values

**Evidence.** Plugin `getStructuredError` directly read `code`, nested `error`, `message`, and `details`; the registered MCP callback wrapper repeated those reads and also called `String(error)`. A thrown Proxy whose getters and coercion throw could therefore replace the initiating mutation error, erase partial/survivor evidence, or make the tool callback reject instead of returning the promised error envelope.

**Required closure.** Guard every direct/nested property read, optional-details copy, and stringification. A hostile thrown value must still resolve to the canonical structured `UNKNOWN_ERROR` envelope, while a readable coded error continues to pass through structurally.

#### F78-19 — annotation recovery invented certainty when count readback failed

**Evidence.** After an annotation setter threw, a failed post-state read left `afterCount` equal to `beforeCount` and reported no partial mutation even when the append could have committed. The outer recovery path did the inverse: it converted any count-read failure to `0`, which could manufacture a false count delta and partial-mutation claim.

**Required closure.** Represent both counts as verified observations rather than guessed numbers. Rows use nullable `beforeCount`/`afterCount` plus required verification flags; an attempted append with unreadable post-state fails safe with `partialMutation:true`, `outcomeUnknown:true`, initiating `error`, recovery guidance, and optional secondary `postStateError`.

#### F78-20 — `create_text` silently accepted unsupported typography inputs

**Evidence.** `fontSize` accepted any number although the pinned Figma contract requires a minimum of 1; callback `||` defaults rewrote explicit zero; and the handler's broad font block swallowed load/assignment failures before returning success. `fontWeight` likewise accepted arbitrary numbers while `getFontStyle` recognizes only the nine 100-through-900 weights and silently mapped every off-grid value to `Regular`.

**Required closure.** Enforce `fontSize >= 1` and the exact supported weight inventory at the MCP boundary, default only omission, and let font-loading or font-size assignment failures flow through Phase 8 cleanup/partial-disclosure rather than returning a false success. Regress zero, negative, off-grid, valid boundary, and post-placement font failures.
