# v2.3.3 PRD: Plugin Type-Check Restoration & Contract-Integrity Closure

> [!CAUTION]
> **Historical adversarial-review draft; superseded.** This is not the current implementation contract. The authoritative v2.3.3 specification is [`../prd.md`](../prd.md), whose Rev 73 removes `create_connection` and `reaction_to_connector_strategy`. Connector requirements below are retained only as evidence of the discarded design.

This document was a proposed product / implementation spec for the **v2.3.3** release of `figma-edit-mcp`. It follows v2.3.2 (Safety Contract Conformance & Atomicity Hardening) and has two tracks:

1. **Type-check restoration (developer infrastructure).** Restore TypeScript type-checking for the Figma plugin source, which is currently silently disabled by a misconfigured `figma_plugin/tsconfig.json`, and add a CI gate so it cannot regress.
2. **Contract-integrity closure.** Close the original code-level Gaps 1, 3, and 5 from [`figma-edit-mcp-gap-details.md`](figma-edit-mcp-gap-details.md), plus the follow-up gaps exposed by the 2026-07-10 adversarial source review and live MCP run on channel `pn68`: an unusable annotation contract, shallow-only strict input validation, incoherent batch envelopes and hidden partial mutation, implicit-parent scope escapes, unsafe connector defaults/clones, unbound plugin/server peers, and unstructured dynamic-page load failures. Gaps 2 and 4 from the original review remain documentation-only; their README correction stays outside this PRD.

> **Origin.** Found during the v2.3.2 Phase 8.5 review (2026-07-06). While adding a `clearTimeout` to `createComponentInstance`, the IDE flagged `setTimeout`/`clearTimeout` as `Cannot find name`. Investigation showed this is **not local** — *no* plugin ambient global (`figma`, `console`, `setTimeout`, node types) resolves under `tsc`, because the plugin tsconfig never loads `@figma/plugin-typings`. The plugin ships via **esbuild** (which does not type-check), so the whole plugin has been shipping **without a type-safety net** and with plugin-wide spurious IDE errors. This release closes that gap.

## The problem

**The bug.** `figma_plugin/tsconfig.json` declares:

```json
"typeRoots": ["../../node_modules/@figma"]
```

The tsconfig lives at `figma_plugin/tsconfig.json`, so `../../node_modules` resolves to the **parent of the repository** (`<repo>/../node_modules`), which does not exist. The repo's actual dependency tree is at `<repo>/node_modules` (one level up from `figma_plugin/`, i.e. `../node_modules`). As a result `@figma/plugin-typings` is **never loaded**, and every plugin ambient global is unresolved.

**Consequences.**

- **No type safety on the most safety-critical code in the project.** The plugin dispatcher (`figma_plugin/src/main.ts`) and handlers enforce the safety contract (scope, name verification, locked/instance guards, batch validation, and effect reporting). Today a wrong Figma API call, a typo'd property, or a bad narrowing in that code is caught only at runtime (or live testing), never by `tsc`.
- **Plugin-wide spurious IDE errors.** `tsserver` reports the same unresolved globals, so contributors see red squiggles on `figma`, `console`, `setTimeout`, etc. across every plugin file — training the team to ignore IDE diagnostics on exactly the code where they matter most.
- **It is invisible to CI.** The plugin is bundled with **esbuild** (`figma_plugin/build.js`), which performs no type-checking, and there is **no `tsc` step** for the plugin anywhere in `package.json`, `figma_plugin/build.js`, or `.github/workflows/ci.yml`. So nothing surfaces the breakage.

**Not a runtime bug.** The shipped plugin works — the globals (`figma`, `console`, `setTimeout`, `clearTimeout`, `TextDecoder`, …) all exist in the Figma plugin sandbox at runtime, and esbuild bundles the source unchanged. This is a **lost safety net**, not a live defect. The v2.3.2 live testing confirms the affected code paths behave correctly.

## Evidence (empirical, 2026-07-06)

Ground-truth measured against the real plugin source (`bunx tsc --noEmit` with probe configs):

| Config | `tsc` errors | Interpretation |
| :- | :-: | :- |
| **Current** (`typeRoots: ["../../node_modules/@figma"]`) | ~309 | @figma typings never load; every `figma`/`console`/`setTimeout`/type-name unresolved |
| **Naive path fix** (`typeRoots: ["../node_modules/@figma"]`) | **309** | *Still broken.* Correcting the path alone does **not** load the typings — the one-line fix a maintainer would try first is insufficient |
| `types: ["@figma/plugin-typings"]` **+ `lib: [es2018, dom]`** | 14 | Types load, but **`dom` conflicts** with the Figma typings — duplicate/redeclared `console`, `fetch`, `Navigation` (TS2451/TS2300). `dom` is the wrong lib |

**Key insight:** the fix is *not* the `typeRoots` path. `@figma/plugin-typings` must be loaded via **`types: ["@figma/plugin-typings"]`**, and the `dom` lib must **not** be added (the Figma typings supply `console`/`fetch`/timers/`Navigation` themselves and collide with `dom`).

## Decisions

> [!NOTE]
> **D1 — Load the Figma typings via `types`, not `typeRoots`; do not add `dom`.** Replace the broken `typeRoots` with `"types": ["@figma/plugin-typings"]`. Keep `lib: ["es2018"]` (no `dom` — it redeclares globals the Figma typings own). This is the configuration empirically shown to load the typings with the fewest residual errors (9).

> [!NOTE]
> **D2 — Fix the residual 9, do not suppress them.** The 9 remaining errors are real type gaps, not noise. Fix each at the source (narrowing, casts, module resolution, one ambient global) rather than blanket-suppressing with `// @ts-nocheck` or loosening `strict`. `strict` stays on. See the triage table.

> [!NOTE]
> **D3 — Add a CI type-check gate, but only after the residual is zero.** Add `check:types:plugin` (`tsc --noEmit -p figma_plugin/tsconfig.json`) to `package.json` and wire it into CI so this regression cannot recur. It must be added **only after D1/D2 bring the error count to 0**—or CI goes red on introduction. The sequencing is by condition, not position: the gate lands as Phase 3, ahead of every Track 2 runtime phase (4–12), so those changes land under its protection. The plugin build stays esbuild (fast, no type-check); the gate is a separate, additive check.

> [!NOTE]
> **D4 — Track 1 scope guard: plugin type hygiene only.** Track 1 fixes the *plugin* tsconfig and its residual errors. It does **not** re-audit the MCP-server tsconfig (`./tsconfig.json`) or use type fixes as cover for runtime refactors. If a residual type fix appears to require behavior change, stop and handle it explicitly under Track 2 (with tests and contract updates) rather than silently altering a live path. Track 2 intentionally contains the runtime changes specified below.

## Track 2 — Safety and tool-contract integrity

> **Origin.** The adversarial review [`figma-edit-mcp-gap-details.md`](figma-edit-mcp-gap-details.md) identified five gaps between the documented safety contract and shipped behavior. The original Gaps 1, 3, and 5 require code changes here; Gaps 2 and 4 remain wording-only. A second source review plus live MCP verification on channel `pn68` (2026-07-10, page-scoped document `MCP Test`) confirmed the original gaps and exposed six additional contract failures. Code/typings evidence is sufficient for defects whose full exploit requires node scope, another loadable page, or a connector template; the live matrix must not mislabel an unreachable fixture as a passed safety test.
>
> **Decision state.** The original eight questions remain resolved; [`open-questions.md`](open-questions.md) remains their decision record. The 2026-07-10 findings supersede the narrow D7/Phase 6 wording and add D10–D14 below. No follow-up finding is left as an implied TODO: it is either in scope with acceptance criteria or explicitly refused as unsupported.

### The problems (verified in code; live where the current scope permits)

**Gap 1 — design-system updates skip right-object verification.** Node writes require ID + current name; variable and style *updates* do not.

- `variable_manage` / `UPDATE_VARIABLE` checks `currentVariableName` **only when supplied** (`figma_plugin/handlers/variableHandlers.ts:1032`); the schema marks it optional (`src/mcp_server/tools/variable.ts:115`). Live-verified: an ID-only value update mutates the variable with no verification; a wrong name is refused only because it was volunteered.
- `style_manage` with `styleId` has **no** current-name verification at all (`figma_plugin/handlers/styleHandlers.ts:13–23`), and its **required** `name` param is applied as the *new* name on every update (`styleHandlers.ts:47`). Live-verified: an update against a stale/mistaken ID both mutates the wrong style **and renames it** to the caller's wrong belief — destroying the evidence of what it was called.
- `variable_manage` / `CREATE_VARIABLE` accepts `collectionId` with no `collectionName` verification (`variableHandlers.ts:963`), unlike `variable_delete`, which requires and verifies it.
- `CREATE_VARIABLE` also accepts omitted `scopes`, despite the agent contract saying scopes are always explicit on create. The handler silently inherits Figma's default instead of rejecting an underspecified global asset.
- `SAFETY.md` **G2** claims name verification covers "every write tool" — contradicted by its own Part B matrix rows for `variable_manage` and `style_manage`, and by the live behavior above.
- The verification error at `variableHandlers.ts:1033` labels the authoritative stored name as "Expected" and the caller value as "got". That convention is arguable rather than objectively wrong; replace it with explicit `stored name` / `received currentVariableName` wording so recovery does not depend on interpreting the operands.

**Gap 3 — create-tool schemas contradict the runtime contract.** `parentNodeName` is `.optional()` in the `create_shape`/`create_frame`/`create_text`/`create_svg`/`create_instance` schemas (`src/mcp_server/tools/create.ts`), while the runtime fails closed when it is absent (`verifyParentName`, `figma_plugin/src/main.ts:151`) and `SAFETY.md` A3/A4 already document it as required. Live-verified: omitting it is refused with `PARENT_NAME_MISMATCH` — a safe but avoidable failure, made worse by the error text ("recheck to ensure correct parentId is passed in"), which misdirects the agent toward the parent *ID* when the parent *name* was simply missing.

**Gap 5 — `node_delete` reports success on partial failure.** `deleteMultipleNodes` returns `success: successCount > 0` (`figma_plugin/handlers/nodeModifiers.ts:294`). Live-verified: a batch that deleted 1 of 2 items returned `{"success":true,"nodesDeleted":1,"nodesFailed":1}`. The other three batch aggregators (`text_set_content`, `annotation_set`, `instance_set_overrides`) already require `failureCount === 0`.

**Gap 6 — `annotation_set`'s MCP contract cannot reach its handler's success path.** The registered item schema exposes `annotationId`, required `categoryId`, `status`, and record-shaped `properties`, but omits `labelMarkdown`. The handler requires `labelMarkdown`, ignores `annotationId`/`status`, accepts array-shaped properties, builds an object that does not match the pinned `Annotation` type, and always appends. The global strict-input wrapper makes only the top-level object strict; nested objects still strip unknown keys. Live-verified: sending nested `labelMarkdown` reached the handler without it and returned `Missing labelMarkdown parameter`; a two-item call returned one failure row and silently omitted the second item. The tool is also incorrectly marked idempotent although append is not idempotent.

**Gap 7 — batch behavior is not one contract.** Five batched write paths (`node_delete`, `text_set_content`, `annotation_set`, `instance_set_overrides`, `create_connection`) disagree on empty input, prevalidation failure, stop/continue behavior, field names, result cardinality, and whether failure may follow mutation.

- All four arrays covered by the original D7 accept `[]` at the schema boundary. Live results are four different shapes: thrown MCP error (`node_delete`), zero-count failure (`text_set_content`), ad-hoc early failure (`annotation_set`), and message-only early failure (`instance_set_overrides`). This directly contradicts the old statement that zero-item batches were unreachable.
- Dispatcher prevalidation errors are thrown before the aggregators, so the old promise that `status` is present "on every return path" cannot hold without distinguishing schema rejection from accepted-call execution or restructuring dispatch.
- Stop-on-first handlers omit unattempted inputs. `totalAnnotations: 2` with `results.length === 1` was reproduced live, so callers cannot know whether a missing row succeeded, failed, or was skipped.
- Duplicate targets are not rejected. Duplicate delete produces one real deletion plus a failure yet reports success; duplicate text/instance targets can produce multiple success rows for one physical object. Parent+child deletes can race in the same `Promise.all` chunk.
- `instance_set_overrides` swaps a target before applying later override fields. A later field failure can therefore report the item failed after its main component already changed; prior successful targets are not rolled back and later targets are omitted.
- `text_set_content` can also mutate before failure: `setCharacters` may replace a mixed/unloadable node font with the first/prevalent/fallback font, then fail to assign `characters` and return false. The item is reported failed while typography changed; a mixed styled-range state cannot be restored by assigning `figma.mixed`.
- Registered output schemas drift from handler outputs (`deletedCount` vs `nodesDeleted`/`nodesFailed`; text's advertised `count` vs replacement counts; connector `results` vs `connections`). `looseOutput` hides rather than prevents this drift.

**Gap 8 — implicit-parent Figma APIs can move/create nodes outside the intended container or editable scope.** `node_flatten` calls `figma.flatten([node])`; the pinned API explicitly defaults the result parent to `figma.currentPage`. A nested source therefore jumps to the page root even in page scope, and after scope-exempt navigation it can land on another page. In node scope, the page is necessarily outside the editable subtree. `create_component_set` similarly combines on the containing page and only reparents afterward; node-scoped calls create outside scope, and any post-combine failure leaves the set there. The ordinary shape/frame/text/SVG/instance/component creators construct under `currentPage` before insertion into the intended parent. The pinned clone methods for the scene-node types reachable by `node_clone` likewise default the duplicate to `currentPage` (the distinct `PageNode.clone()` root behavior is rejected by the destination-scope gate), while the handler reparents only afterward. Most paths are same-stack transients, but `create_text` awaits font work before insertion and is observably out of scope across asynchronous yields. These paths violate containment by construction even when IDs and names were prevalidated.

**Gap 9 — `create_connection` combines scope bypasses, hidden mutations, unsafe persistence, and false success.** Automatic template discovery scans `figma.currentPage` without scope validation and stores only an ID in plugin-wide `clientStorage`; the available root ID is not a durable cross-file cache key, so a persistent default cannot be safely partitioned by document. `connectorId` has no name-verification field. `ConnectorNode.clone()` defaults to `currentPage`; nested endpoints create cursor SVG nodes through another implicit-current-page API; per-item failures do not remove cloned connectors/cursors; and the aggregate unconditionally returns `success: true`. The tool cannot bootstrap its first connector through MCP. The pinned API marks direct connector creation FigJam-only, but does not prove that cloning an existing connector is unavailable in Figma Design; editor restriction must therefore be stated as release policy, not an inferred API fact. Channel `pn68` had no connector template, so the per-item exploit was not live-reachable; source and pinned typings establish the remaining defects.

**Gap 10 — a live run cannot bind commands to the plugin peer that reported its build.** MCP initialization reports the server package version, but `get_connect_payload`/`channel_join` omit the plugin version. The plugin posts `PLUGIN_VERSION` only to its UI. More fundamentally, the socket broadcasts a channel message to every other peer; plugin joins carry no client type or peer identity. One plugin can answer a build handshake while a different plugin answers a later write. `resetChannel()` also clears only MCP client state and does not leave the socket room. The `pn68` run therefore proved the checked-out server was 2.3.2 but could not prove which plugin peer executed a command. A self-reported semver is not cryptographic attestation, so Phase 14 must limit its claim to a peer-bound, version/protocol-reported handshake.

**Gap 11 — dynamic-page failures are raw, all-or-nothing, and unsafe for document-wide decisions.** `page_info` lists unloaded pages successfully, but detailed reads call `loadAsync()` without per-page recovery. On `pn68`, details for Pages 2/3 and navigation to Page 2 failed with Figma's raw 10-second connection error while Page 1 remained usable. Plugin errors are currently flattened to strings in `main.ts`, relayed as strings by the UI, and reconstructed as plain `Error` objects by `figma-client.ts`, so promised stable failure codes cannot survive end to end. Document-wide consumer checks such as `variable_delete` traverse every page; they must not delete when any page could not be loaded/scanned, but the contract neither exposes partial read errors nor states the fail-closed rule.

### Decisions

> [!NOTE]
> **D5 — Bring design-system updates up to the node-write standard (Gap 1).** Fail closed on a missing or mismatched current name, exactly like `verifyNodeName`:
> - `UPDATE_VARIABLE`: `currentVariableName` becomes **required** — in the `variable_manage` schema and in the handler (absent ⇒ reject, mismatch ⇒ reject, before any mutation).
> - `CREATE_VARIABLE`: new **required** `collectionName`, verified against the resolved collection's name before `createVariable` (same pattern as `variable_delete`), and `scopes` becomes required-on-create in both server refinement and plugin defense-in-depth. Empty scopes are allowed only if Figma accepts them and the caller supplied them deliberately; omission is rejected.
> - `style_manage` with `styleId`: new **required** `currentStyleName`, verified against the resolved style's name before any mutation.
> - `style_manage` `name` becomes **optional at the schema level**: the handler enforces it on create; on update it renames only when explicitly provided. This removes the accidental-rename side effect — a properties-only update no longer has to pass (and therefore overwrite) the name.
> - Replace the ambiguous `Expected`/`got` variable error with explicit stored/received field labels.
> - **Advertised-schema mechanism (supersedes Q1/Rev 3).** Runtime-only `.superRefine()` requirements are insufficient because they do not make fields required in `tools/list`. `variable_manage` becomes `z.discriminatedUnion("action", …)` over strict `CREATE_COLLECTION`, `CREATE_VARIABLE`, and `UPDATE_VARIABLE` members; `style_manage` gains required `action: "CREATE" | "UPDATE"` and uses the same strict structural-union pattern. `CREATE_VARIABLE` structurally requires `name`, `collectionId`, `collectionName`, `type`, and `scopes`; `UPDATE_VARIABLE` structurally requires `variableId` and `currentVariableName`. Style `CREATE` requires `type` and `name`; style `UPDATE` requires `type`, `styleId`, and `currentStyleName`, with `name` optional. Member-level refinements remain only for relational rules such as “value requires a valid mode” or “at least one field changes.” Tests assert both `safeParse` behavior and the emitted `tools/list` JSON Schema.
> - Replace `looseOutput` here too. Variable results are a strict output union keyed by echoed action: collection creation returns `{action,id,name,defaultModeId,modes:[{modeId,name}]}`; variable create/update returns `{action,id,name,key,type}`. Style create/update returns strict `{action,id,name,type}`. Registered-callback tests cover every action and forbid extra/missing fields.
> - Resolve the full action plan before the first write: target identity/name, mode, value type/alias, scopes, style-property compatibility, and every variable binding. Snapshot every field the plan can change. Predictable failures return before mutation; unexpected failures restore the snapshot, reporting `MUTATION_PARTIAL` with before/after details if exact restoration is impossible. In particular, do not rename or change description/scopes before discovering a bad `modeId`, and do not apply style properties before discovering a bad later binding.

> [!NOTE]
> **D6 — Every caller-placed creation names an explicit verified parent (Gap 3 + Gap 8).** Remove `.optional()` from `parentNodeName` in `create_shape`/`create_frame`/`create_text`/`create_svg`/`create_instance`. Also make both `parentId` and `parentNodeName` required for `create_component_set`; the previous no-parent exception is incompatible with A3/G2 and enables page-level placement outside node scope. Its component array is `.min(1)`, matching the pinned non-empty `combineAsVariants` contract, and its properties array remains the deliberate server requirement `.min(1)`. Structural transformations such as flatten, group, clone, and frame-to-component conversion may derive placement from prevalidated sources, but D11 requires their derived destination parent to be resolved, verified, and preserved. Reword `PARENT_NAME_MISMATCH` to distinguish missing from mismatched and direct the caller to `node_info`, not toward replacing a correct ID. `create_connection` gets its narrower page-parent contract under D12.
> For component sets, normalize and reject duplicate component IDs; require property names and values to be trimmed/non-empty, delimiter-safe (no `=` or `,`), and unique after normalization; require each strict component item's `propertyValues` to contain exactly one value per property; and reject duplicate property-value combinations. Resolve every item as a verified, unlocked, local, in-scope `COMPONENT` that is not already inside another component set; require all components and the destination to share one page; verify the destination accepts children and is not any source component or its descendant; and complete these checks before renaming or combining. These are accepted-call preconditions when they require node resolution and schema/refinement errors when visible from arguments alone.
> **Verification split (Q2).** Once the schema requires the field, a conforming client can no longer reach the plugin's "missing" branch—the message keeps that branch as defense in depth for older/non-conforming clients. Phase 5 schema tests cover omission; the Phase 14 live matrix covers a mismatched supplied name against the reworded plugin error.

> [!NOTE]
> **D7 — One execution-eligible batch contract, with honest effect state (Gaps 5 and 7).** `node_delete`, `text_set_content`, `annotation_set`, `instance_set_overrides`, and creation-only `create_connection` share a typed envelope after both request-level and command-level prerequisites succeed:
> - Every input array is `.min(1)`. A schema-invalid call (including `[]`, unknown nested keys, a normalized duplicate ID caught by refinement, or a malformed item) is an MCP validation error and intentionally has **no** execution envelope because the operation was never accepted. A non-conforming client that invokes plugin dispatch directly gets structured command error `INVALID_BATCH`, with no mutation and no execution envelope.
> - A pre-dispatch transport/session/global-prerequisite failure—no joined channel, peer already disconnected, invalid/deleted scope, edit permission disabled, version/protocol skew, unsupported editor/scope, or required page-load failure—is a structured command error with no batch envelope and **must occur before mutation**. These errors describe why the command could not become execution-eligible.
> - Generate a unique `commandId` before dispatch and carry it through socket correlation, plugin execution, progress, and the terminal response. If the command was dispatched but its correlated terminal response is lost to timeout/disconnect, return D9 code `COMMAND_OUTCOME_UNKNOWN` with strict details `{commandId,tool,dispatchedAtMs,targets,recoveryTool}` where `targets` uses the tool's immutable target schema and `recoveryTool` is a registered read-tool enum. Return **no** batch envelope; the client cannot truthfully infer whether effects are none, committed, rolled back, or partial. Never retry this path blindly. Tool-specific re-discovery is mandatory (annotation uses its digest/list procedure), and subsequent commands remain blocked if the peer binding was lost. Tests cut the transport immediately before dispatch, after dispatch/before the first write, and after an injected write.
> - Once prerequisites succeed, every execution-eligible call **whose correlated terminal response arrives** returns `status: "success" | "partial_success" | "failed"`, `effectState: "none" | "committed" | "rolled_back" | "partial"`, `success`, `requestedCount`, `succeededCount`, `failedCount`, `skippedCount`, and `results` with exactly one row for every index `0…requestedCount-1`, in input order. `status` is derived only from row outcomes: all succeeded ⇒ `success`; at least one succeeded plus any failed/skipped ⇒ `partial_success`; no succeeded ⇒ `failed`. `success === (status === "success")`; `requestedCount === succeededCount + failedCount + skippedCount`; `results.length === requestedCount`.
> - Each row includes `index`, an immutable `target` descriptor captured before mutation, `status: "succeeded" | "failed" | "skipped"`, `mutationState: "none" | "committed" | "rolled_back" | "partial"`, and a tool-specific strict `effects` object when post-execution state must be disclosed. `none` means no write occurred; `committed` means an intended effect remains (including a successful append/delete); `rolled_back` means a write occurred but the exact prior state was restored; `partial` means cleanup/restoration is incomplete or the terminal state is unknown. A successful no-op may be `none`; a failed restored row is `rolled_back`; skipped is always `none`.
> - Valid row combinations are closed: `succeeded` permits `none|committed` and forbids `error`; `failed` permits `none|rolled_back|partial` and requires `error`; `skipped` requires `none` and `error`. A failed operation that leaves any intended or unintended effect is `partial`, not `committed`. Strict discriminated row unions and property tests reject every other combination.
> - Top-level `effectState` is orthogonal to `status` and is derived from rows with precedence `partial` > `committed` > `rolled_back` > `none`; therefore `status:"failed", effectState:"partial"` is valid and necessary. Failure/skipped rows carry the strict D9 `ContractError`. Partial rows disclose every known created/leaked ID and before/after identity needed to inspect state. Blind retry is never inferred from row status alone.
> - `target` shapes are exact: delete/text `{nodeId,nodeName}`; annotation `{nodeId,nodeName,payloadDigest}`; instance `{sourceInstanceId,targetNodeId,targetNodeName}`; connection `{startNodeId,startNodeName,endNodeId,endNodeName,connectorId,connectorName,parentId,parentNodeName}`. `effects` shapes are likewise exact: text `{beforeCharactersSha256?,afterCharactersSha256?,beforeFontName?:FontName,afterFontName?:FontName}`; annotation `{beforeCount,afterCount}`; instance `{originalMainComponentId?,currentMainComponentId?}`; connection `{createdConnectorId?,cursorNodeIds,leakedNodeIds?}`. Text digests are lowercase-hex SHA-256 of the exact UTF-8 characters with no Unicode normalization; `FontName` is strict `{family,style}`. The immutable target remains present even if execution deletes or renames it; effects never overwrite caller intent.
> - Dispatcher prevalidation for an accepted call resolves every item and returns a failed envelope, not a thrown per-item error: every offending row is `failed`, otherwise-valid rows are `skipped`, every row has `mutationState:"none"`, `effectState:"none"`, and no mutation occurs. Stop-on-first mutation behavior may remain where continuing is unsafe, but all remaining inputs are explicit skipped rows.
> - `node_delete`, `text_set_content`, and `instance_set_overrides` reject duplicate targets before mutation. Normalize URL/API node-ID spellings (for example `1-2` and `1:2`) before duplicate or ancestor checks. Argument-visible duplicates are schema/refinement errors; delete ancestor/descendant overlap requires resolved nodes and returns an accepted-call failed envelope with no mutation. Annotation may repeat a node because multiple annotations are legitimate; its input index and payload digest identify the append attempt.
> - Handler outputs and registered `outputSchema` field names are identical, typed, and `.strict()` at every affected envelope/row/descriptor/error layer; these paths do not use `looseOutput` or catchall. If forward-compatible data is needed, it goes under a named typed `metadata` object. `node_delete` standardizes on common counts; instance reports target counts separately from `overrideCount`; connector uses the same envelope.
> - Prevalidation covers predictable, inspectable failures—not every possible runtime setter failure. Instance handling checks recursive dependency, source/target shape, and the intended setter strategy; text handling resolves/preloads required fonts and rejects mixed-font content replacement before mutation in v2.3.3. Each supported path snapshots exactly the fields it intends to mutate. Unexpected post-write failures trigger best-effort per-item rollback; incomplete restoration is `partial`, never a false no-op.

> **D13 — Peer-bound version/protocol handshake (Gap 10).** Add one canonical machine-readable protocol contract containing the complete plugin command request/result/error schemas, scope/gate schemas, progress/correlation messages, and shared envelope versions. `gen:protocol-digest` serializes it with RFC 8785 JSON Canonicalization Scheme (JCS), computes SHA-256, and emits the same lowercase-hex generated constant into server/plugin builds. `check:generated` fails if either value is stale; prove-red tests change one field's requiredness/type and an error-detail shape. The digest is not an independently handwritten semver alias.
> Scope readiness is authoritative in plugin main, not the UI. After validating and committing scope/edit permissions, plugin main returns a monotonically increasing `scopeRevision`, fresh opaque `scopeReadyNonce`, and strict `scopeIdentity: {documentRootId,scopeRootId,scopeType,allowEditNode,allowEditVariable,allowEditStyle,editorType}` using normalized node IDs and exact lowercase enums/booleans. Raw `get_connect_payload` is plugin-owned and returns plugin version/digest/editor/document/scope readiness only—it cannot claim server/socket fields. Immediately after binding, the server requests this authoritative payload from the selected peer and requires every join-advertised plugin identity/scope field to match; mismatch unbinds the pair. Only after that comparison does the server compute `scopeFingerprint = SHA-256(JCS(scopeIdentity))` for the aggregate join result, avoiding trust in UI-computed state.
> The socket assigns a cryptographically random connection-lifetime `peerId`; an MCP join receives a `sessionId`. It atomically reserves a channel as exactly one plugin peer plus one MCP session, binds that pair, and routes commands/responses only within it; response correlation includes `sessionId` + `peerId`, and mismatched responses are ignored. Zero plugin peers returns `PLUGIN_PEER_UNAVAILABLE`; a second plugin returns `PLUGIN_PEER_AMBIGUOUS`; a second MCP client returns `CHANNEL_IN_USE`. There is no unspecified pairing-token branch. The selected binding and reported scope/version/digest remain prerequisites for every tool, not only writes, and are invalidated immediately when that plugin peer leaves: an undispatched call gets `PLUGIN_PEER_DISCONNECTED`, while an in-flight dispatched call with no terminal response gets D9 `COMMAND_OUTCOME_UNKNOWN`.
> Successful `channel_join` is the server/socket-owned aggregate and returns required `serverVersion`, `pluginVersion`, `protocolDigest`, `editorType`, `peerId`, `sessionId`, and scope fingerprint. Missing/`unknown` plugin version returns `PLUGIN_VERSION_UNAVAILABLE`; missing digest returns `PLUGIN_PROTOCOL_UNAVAILABLE`; unequal known versions return `VERSION_MISMATCH`; unequal digests return `PROTOCOL_MISMATCH`. Every failed join triggers a real socket-level leave/unbind (or close/reconnect), clears all local channel/scope state, and blocks every subsequent tool until a successful join. Implement and test explicit leave/reset in the socket and `figma-client`, including mismatch → detach → matching rejoin, selected-peer disconnect, scope-change invalidation, and two plugin peers (matching plus stale) with no cross-response. This is a peer-bound self-reported build/protocol check, not cryptographic artifact attestation; Phase 14 may claim only that the bound peer reported and enforced the expected identity.

Apply this to collection deletion, including apparently empty collections.
> Use shared constants `PAGE_LOAD_TIMEOUT_MS = 12_000`, `PAGE_SCAN_CONCURRENCY = 5`, and `PAGE_SCAN_DEADLINE_MS = 60_000`. Schedule pages in deterministic normalized order with at most five active attempts. Emit exactly one command-level progress heartbeat at 2,000 ms and every 2,000 ms thereafter while any page work remains, containing active/pending/succeeded/failed counts; never emit heartbeats more frequently, and do not let them extend either deadline. At the command deadline, start no more work and mark every pending or unstarted page once with `PAGE_SCAN_DEADLINE_EXCEEDED`; release the serialized command queue within the next event-loop turn. Associate attempts with a command token so late `loadAsync()` settlement cannot alter a returned result or authorize later mutation. Constants are centralized and fake-clock tested, including a 25-page all-timeout run and a document with more pages than can start. A multi-page read may return partial data only with `coverage.complete:false`; a destructive operation never does.

### Compatibility posture

These are **deliberate breaking contract repairs** for agent callers. Unverified writes now fail with recovery guidance; every caller-placed creation has explicit verified placement; empty/unknown nested batch input fails at the schema boundary; execution-eligible batches return a new exact envelope; connector default-management modes are removed in favor of an explicit template on every creation call; connector creation is editor/scope-aware; and unsupported annotation update fields are removed in favor of a working append contract. Gap 3's five existing runtime refusals simply move earlier, but `style_manage` gains an action discriminator and `create_component_set`, connectors, annotation callers, and result parsers require migration. The `CHANGELOG.md` must include a before/after request and response example for every affected tool family—not only a list of fields.

**Hard cutover confirmed (Q8).** There is no warn-only transitional release. A warning attached to a successful result is precisely the signal agents are known to ignore. Schemas, plugin, bundled guides, and live plugin build identity must ship together; D13 refuses mixed or ambiguously routed peers instead of attempting compatibility guessing.

## Risks & mitigations

| Risk | Likelihood | Mitigation |
| :- | :- | :- |
| A residual fix accidentally changes runtime behavior on a live-verified path | Low | D4 stop-and-escalate rule; `check:plugin` rebuild-diff catches any unexpected emitted-JS change; the fixes are types/casts/config only |
| Fixing `shared/nodeTypes.js` resolution un-masks further errors in `shared/` | Low–Med | Scope the `include` to what the plugin imports; if `shared/` itself has errors, triage or exclude with a recorded note rather than expanding scope |
| `TextDecoder` ambient declaration drifts from a future `@figma/plugin-typings` that adds it | Low | Prefer the typings if a version provides it; otherwise a one-line ambient `declare` with a comment pointing here |
| Turning on the CI gate blocks unrelated PRs if the residual isn't truly zero | Low | D3 sequencing — gate added only after Phase 2 reaches 0; prove-red/prove-green before wiring into CI |
| Existing agent workflows break on required verification/parent fields or the new batch envelope | High | Intended hard cutover; ship schemas/guides/plugin together, refuse version skew, provide before/after examples and one-round-trip recovery messages; promote to 2.4.0 before implementation if downstream schema pinning is discovered |
| `SAFETY.md` matrix and `safetyContract.test.ts` drift apart during the change | Low | D8 same-change rule; the bidirectional mechanical diff fails CI on any mismatch |
| Common batch refactor still hides handler/schema drift behind `looseOutput` | Med | Ban `looseOutput`/catchall from affected inputs and outputs; invoke registered callbacks and validate every branch against strict registered schemas |
| A failed item mutates before error and rollback is incomplete | Med | Prevalidate only predictable failures; snapshot exact tool-specific fields; best-effort rollback; `rolled_back` or `partial` mutation state plus before/after/created IDs and explicit retry disposition |
| A response is lost after a write was dispatched | Med | Correlated command IDs; `COMMAND_OUTCOME_UNKNOWN` without a fabricated effect state/envelope; block on lost binding; tool-specific re-discovery before retry; before/after-write transport-cut tests |
| Recursive strictness rejects fields older clients had silently ignored | Med | Desired correction of silent intent loss; migration examples identify removed/misspelled nested fields; MCP validation error names the exact path |
| Annotation repair accidentally promises update/delete or safe retry semantics Figma cannot verify | Med | Append-only contract removes `annotationId`/`status`; payload digest/counts and list-before-retry guidance; explicitly report when identical-append outcome is indeterminate |
| Direct-parent component-set/flatten changes layout order or variant semantics | Med | Preserve original flatten index; component set requires an explicit destination; snapshot/restore names around combine; live visual/parent/variant assertions and before/after trees |
| A no-parent Figma creator exists under `currentPage` for part of one synchronous stack | Med | State the observable boundary honestly; resolve destination first, insert as the immediate next call before any await/setter/progress, clean up later failure, and record the residual in `SAFETY.md` |
| Connector cleanup leaves hidden nodes after an endpoint/font failure | Med | Track every clone/cursor ID per item; `finally` cleanup; partial-state reporting if cleanup fails; page-scope-only support until parent-aware APIs exist |
| Peer-bound routing changes the socket's broadcast behavior or strands stale room membership | Med | One-to-one pair table, session/peer response correlation, explicit leave/unbind, disconnect invalidation, and two-plugin integration tests |
| Version/protocol mismatch refusal blocks an otherwise readable file | Low | Return reported identities and actionable reinstall/rebuild guidance; detach cleanly; recovery test with the matching plugin. Safety takes precedence over mixed artifacts |
| A page-load timeout settles late or makes document-wide destructive operations unavailable | Med | Command-token late-result suppression, exact progress accounting, typed partial reads, and fail-closed destruction rather than treating an error as zero consumers |
| Expanded Track 2 scope makes v2.3.3 too large to review safely | Med–High | Land phases in dependency order under the type gate; require per-decision commits/rebuild diffs and the full contract/live matrix. If implementation cannot stay reviewable, split the release or promote/re-scope explicitly—do not silently defer a safety gap |
